- 同一需求版本已有未删除的关联报价时返回 409，提示已有报价编号；同一修订链的行锁覆盖查询与创建，防止并发点击产生多份。改价应进入原报价新增版本。历史已生成的多份报价不自动合并或删除。
- 同序 CRM 服务审批摘要新增 `business_stages.quotation: {status, label, review_stages}`，CRM 手动同步结果后保存在 OA 记录 result 中。

- 正式 PDF、发送登记及邮件、转正式订单等继续使用共享后端校验。没有新阶段摘要的旧审批，仅兼容整单已通过；有阶段摘要时优先采用该结论，整单 approved 不能覆盖“报价复核未通过”。
- 尚未通过报价阶段时，业务文件生成只能输出带原因和水印的 draft 文件；成本完整性和其他原有校验继续执行。已存档正式文件下载同样校验，防止从通用文件接口绕过。

## 2026-11-25 实测与回调（阶段闸门口径修正）

本地验证（CRM 8009 → OA 8791，库 restored_oa_20261117）结论：

- 打样模板（`form-21e21dedad1d410c93e996930d012bb3`，2026-11-17 发布）只有一个 initial 节点、两人或签，**没有 sample_review 节点**；"使用流程"是附件 Excel，不是流程节点。
- 询价模板（`key-account-product-inquiry`，2026-11-18 发布）为 initial（直属主管）→ 报价审批（两人或签），**无"是否通过"与"报价方案"字段**。
- 因此 OA 侧 `sample_stage` / `quotation_stage` 均返回 None，摘要不产出 `business_stages`；真实记录（打样 481/473/469、询价 471）可证。**OA 侧代码固定，不改。**

据此修正 CRM 判定口径（`oa/business_gates.py`、`oa/sample.py`）：

- 无阶段摘要（`business_stages` 为 None 或 `{}`）→ 按**整单 approved** 判断（适配现行单/双节点模板）；
- 有阶段摘要但缺所需阶段 → **拒收**（防半截/异常回包），打样回写保持 pending；
- 有阶段摘要且所需阶段存在 → 按阶段判定（OA 将来升级多节点模板后自动接管，无需再改代码）。

`review/repro` 的 b09_01/b10_01 两条断言按实测作废（skip 标注原因），不再是验收标准。
