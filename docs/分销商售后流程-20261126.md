# 分销商售后流程（2026-11-26 版）

> 口径：售后必须挂订单；业务员申请、主管审核、仓库确认收货、财务确认退款。财务不改金额、不手选抵扣；系统按订单当前欠款自动先冲，剩余才现金退。

## 一、流程

1. **业务员发起售后**（`order:manage`）
   - 必须选一张订单；
   - 填售后类型、原因、退货数量（只退已发货的产品）；
   - 填退款金额构成：货款退款、运费退款、改价/其他调整（调整可正可负），系统合计为退款总额；
   - 填退款打款方式（默认线下转账）、收款账户、退回物流单号（选填）；
   - 上传《分销商退款登记表》附件（必填）；
   - 提交后状态：`reviewing`（待主管审核）。
2. **主管审核**（`order:assign`）
   - 审核数量、原因、金额构成和申请附件；
   - 通过 → `warehouse_pending`（待仓库确认收货）；驳回 → `rejected`，释放可退数量；
   - 主管可以审核自己提交的申请，列表标“本人审核”，审计写 `self_reviewed=true`；业务员、财务不能审核。
3. **仓库确认收货**（当前用 `order:assign` 代仓库操作）
   - 点清实际收到的数量，填收货备注、物流单号；
   - 确认 → `completed`（待财务退款）。没有仓库确认，财务不能退款。
4. **财务确认退款**（`payment:manage`）
   - 只能按审核后的退款总额处理，不改金额；
   - 系统自动计算：
     - `可抵扣上限 = min(订单当前未付款, 应收计划未结余额)`
     - `自动抵扣 = min(退款总额, 可抵扣上限)`
     - `现金退款 = 退款总额 - 自动抵扣`
   - 现金退款 > 0 必须填退款流水/凭证说明；现金退款 = 0 不用填；
   - 全部抵扣 → `settled`（已抵扣结清）；有现金退 → `refunded`（已退款）。
5. **作废**
   - 仓库确认后、财务退款前可以作废（`completed` / `warehouse_pending`）；
   - 历史已抵扣单按原 `SalesReturnPlanAdjustment` 快照恢复应收；
   - 已退款/已抵扣结清不能作废，只能线下处理并保留凭证。

## 二、金额怎么分（以订单 1000、已付 200、未付 800、退 700 为例）

| 项目 | 金额 |
|---|---:|
| 订单总额 | 1000 |
| 客户已付款 | 200 |
| 客户未付款 | 800 |
| 本次退款总额 | 700 |
| 系统自动抵扣未付款 | 700 |
| 现金退给客户 | 0 |
| 处理完后客户还欠 | 100 |

如果退 250（客户仍欠 800）：

- 自动抵扣 250，现金退 0，客户还欠 550。
- 如果客户只欠 100、退 250：自动抵扣 100，现金退 150，客户欠款归 0。

## 三、状态

| 状态 | 含义 | 下一步 |
|---|---|---|
| `reviewing` | 待主管审核 | 主管通过/驳回；申请人可取消 |
| `warehouse_pending` | 待仓库确认收货 | 仓库确认；可作废 |
| `completed` | 待财务退款 | 财务确认退款；可作废 |
| `refunded` | 已退款（可能含抵扣+现金） | 终态 |
| `settled` | 全部自动抵扣，无现金退 | 终态 |
| `rejected` / `cancelled` / `voided` | 驳回 / 取消 / 作废 | 释放可退数量（历史抵扣单按快照恢复应收） |

## 四、权限

| 动作 | 权限 |
|---|---|
| 发起售后、取消申请 | `order:manage` |
| 主管审核、仓库确认 | `order:assign` |
| 财务确认退款 | `payment:manage` |
| 查看售后/金额 | `order:view` / `payment:view` |

## 五、当前边界

- 一张售后单可以包含多个产品，尚未强制“一个产品一张售后单”；
- 聚水潭绑定、商品改价公式（售价-包装费）未实现，当前用“改价/其他调整”字段承接；
- 申请附件只校验“当前账号上传、文件存在”，未校验是否挂到该订单的业务附件；
- 仓库没有独立角色，暂由主管/管理员代确认。
