# 全流程走查与撤回点（2026-11-25）

## 一、结论先说



1. **主线能走通**：线索 → 客户 → 商机 → 核价 → 报价（审批 / 发送 / 客户接受）→ 订单草稿 → 正式订单 → 应收 → 排批次 → 实发 → 回款登记 / 财务确认 → 签收 → 完成，本次用真实接口在隔离库跑通，单据编号见第三节。

2. **不是所有环节都能撤回**。已确认 5 个死路，其中 K1（已确认回款后不能取消订单）、K2（已发货后没有退货入口）已于 2026-11-25 按主人拍板的 A 方案修复并跑通；目前仍剩 3 个：K3 打样已批准不能终止、K4 订单草稿不能作废、K5 已发送报价不能「我方关闭」。

3. 其余撤回点大多已经存在且提示清楚（合同可作废 / 撤回 OA、报价可撤回审批 / 作废草稿、打样草稿可删、询价可归档、任务可取消）。缺的是 "流程走到一半、客户不要了 / 我方不做了" 时的**终止动作**。

## 五、已确认的死路（含本轮已修复）

### K1（P0，已修复）已确认回款的订单无法取消，提示的 "人工处理回款" 没有入口



* 现象：`POST /orders/1/cancel` → `422`，"该订单有 1 笔已确认回款，不能直接取消；请先人工处理回款"。

* 证据：`backend/app/modules/order/router.py:987`。

* 但回款侧只有 "确认 / 驳回 / 改待确认记录 / 改分配"，**没有作废已确认回款的接口**：`backend/app/modules/payment/router.py:939` 明确 "回款已确认，不能再修改"；OpenAPI 里 payments 下没有 void/reverse。

* 影响：客户取消、我方放弃、订单取消都会在这里永久卡住；钱已经进了账，系统却不给任何纠错路径。

* **修复（2026-11-25，主人拍板 A 方案）**：
  * 后端新增 `POST /api/v1/payments/{payment_id}/void`（`payment:manage`）：只允许 `confirmed → voided`；重复作废幂等；原因必填（2–255 字）；多期分配全部冲回；应收期按剩余已收金额回退（`paid → pending / overdue`）；原确认人与确认时间保留，新增 `voided_by / voided_at / void_reason`；写审计、通知跟单人；已收金额归零时自动撤销「付定金/收款」跟单节点；订单财务汇总与回款率排除 `voided`。
  * 前端订单详情「回款记录」新增「作废回款」按钮与原因弹窗；作废后置灰并显示作废人/原因；取消订单弹窗改为“请财务先在「回款记录」作废”。
  * 迁移：`backend/alembic/versions/20261125_payment_void_fields.py`（revision `b7d3f9a2c4e1`）。
  * **真实接口回归**：隔离库 `crm_iso_flow_20261125` 中，财务王五作废 8910 → 已收 0 / 未收 29700、两期应收回到 `pending`、回款记录显示 `voided`；业务员调用 403；重复作废返回“已经作废”；随后订单从「已完成」回退「已取消」成功。单测 `tests/test_payment_void.py` 5 条全绿。
  * **顺带修复 K1b**：`POST /orders/{id}/cancel` 原来没有请求体，“已完成”订单回退永远卡在“必须填写理由”；现支持可选 `{reason}`，前端已完成订单的取消弹窗必填理由，理由进状态变更留痕。

### K2（P0）已发货批次不能取消，提示 "走退换流程"，但系统没有退换流程 —— **已修复（2026-11-25，A 方案）**



* 现象：`DELETE /orders/1/shipments/1` → `400`，"已发货的批次不能取消，请走退换流程"。

* 证据：`backend/app/modules/order/service.py:1214`。

* 全仓搜索没有退货 / 退换 / 退款业务模块；ERP 侧只有外部售后的核定台账，且 "退货退款核定口径" 尚未拍板（`app/modules/erp/reconcile.py:21`）。

* 影响：发错货、客户拒收、部分退货都没有地方登记，只能线下处理，CRM 台账与事实脱节。

* **已落地（A 方案：轻量销售退货登记，2026-11-26 调整金额口径）**：
  * 入口：订单详情 →「退货记录」页签；只按产品/数量登记，不用选批次，系统按订单明细汇总已发/已退数量，不再拆发货批次；超退会被拦并提示还能退多少。
  * 状态：`reviewing` 待主管复核（登记时已填退款金额）→ `completed` 待登记退款 → `refunded` 已退款；`pending` 只兼容历史旧单（当时没有填金额）；`rejected` 主管驳回（释放占用的可退数量，可重新登记）；另有 `cancelled`（复核前/历史待补金额时可取消）、`voided`（主管通过后未实际退款可作废）。
  * 金额口径：**登记时就填本次退款金额（含货款和运费），不再等主管通过后另填**；登记时按订单单价折算的“参考金额”只作提示，不是最终应退。主管通过后，财务可以核对/修改退款金额，每次修改都写审计（改前金额、改后金额、操作人、说明）；财务再登记实际退款。登记时可上传一份退款凭证附件（银行回单/转账截图/客户签收单，单个不超过 20 MB，存文件中心，不复制原件）。
  * 不再自动抵扣：2026-11-26 主人明确，新退货不再自动“抵扣客户未付款、剩余才退还客户”。退款金额单独记录，订单原有应收计划不因新退货被冲减；界面也不再显示抵扣/退还分账预览。
  * 退款分配：新流程 `offset_amount=0`，`refund_amount=settled_goods_amount`；历史 `freight_refund_amount` 字段保留但新单固定 0。历史抵扣单保留原 `sales_return_plan_adjustments`，作废时按原快照恢复。
  * 回退：登记后可取消；主管通过后、实际退款前可作废，新流程只释放可退数量，不再恢复应收（本来就没冲）；历史抵扣单仍按原快照恢复。已登记实际退款不能作废，也不能再改金额；已登记退款后附件不能再改。
  * 互斥：订单已有已处理/已退款退货时，回款作废会被拦住，防止“没收到钱却已退款”；未退款的退货可先作废，再作废回款。
  * 权限：业务员/主管登记、取消；主管复核（有 order:assign 的主管/管理员都能复核，登记人自己登记的也可以自己复核，界面标「本人复核」并写审计；业务员、财务不能复核）；财务修改退款金额、登记实际退款、作废（payment:manage）；业务员没有 payment:manage 不能改金额。原发货事实与库存均不动。
  * 批次口径（2026-11-26 调整）：业务确认退货不需要追到具体发货批次。退货明细只挂订单明细，`shipment_batch_item_id/batch_id` 允许为空，历史退货单保留原批次值；可退数量按“该订单明细所有已实发批次合计 - 所有活跃退货合计”计算，前端不再拆批次，后端也不再按批次号分摊。
  * 验证：16 条单测（含登记金额落库、主管通过直接进入待退款、财务改金额审计、改金额不碰应收、无自动抵扣、财务不能改已退款单、历史抵扣单不能改金额、历史抵扣单作废恢复、主管自审留痕、业务员不能复核、同产品分两批发货不重复算参考金额、驳回释放数量、退款附件序列化）；隔离库真实接口 E2E 仍需按新口径重跑“登记→主管复核→财务改金额→退款→回款闸门”。

* 现象：打样状态机只有 `pending/approved/rejected/shipped/signed`，没有取消 / 终止；可删除仅限 `pending/rejected`，且已制作 / 已寄送一律拒绝。

* 现象：`/order-drafts` 只有 create/get/patch/confirm/documents；草稿状态只有 `draft`，转正式后不可编辑，但草稿本身永久留存。

* 代码自己写明：新建版本会切换当前版本、把报价改回草稿、结束旧版审批，" 历史资料保留，但**没有撤销入口**"（`backend/app/modules/quote/router.py:1032`、`:1054`）。

## 六、上手摩擦与指引现状

做得好的地方（本次实测有效）：



* 报错基本都带 "为什么 + 下一步"：主数据未确认会指名 SKU 并让新建版本；运费未填会指名去「附加费用」；客户无负责人会让先补归属；打样未审批会指到同序 OA；订单取消会列出已签合同 / 已确认回款。

* 前端已有 `GuardedButton` / `BlockedHint` / `workflow-guide`，灰按钮旁边常驻原因。

需要补指引的地方（不改业务规则也能做）：



1. **流程总览**：新用户不知道 "线索→客户→商机→报价→打样 / 合同→订单→回款" 的先后与卡点。建议在工作台或帮助入口放一张可点击的流程地图，标出每一步的入口、前置条件和撤回动作。

2. **主数据确认要前置**：报价明细生成前若 SKU 未确认，后面即使补确认也要新建版本。建议在新建报价 / 加明细时就把 "主数据未确认" 作为必读提示，并提供 "确认主数据" 的直达入口。

3. **运费 0 元也要显式确认**：建议在附加费用区默认显示 "运费未确认" 红点，而不是等提交时才报错。

4. **回款权限**：业务员在订单里点 "生成应收" 会得到 "需要 payment:manage"，建议灰按钮直接写明 "由财务生成"。

5. **客户归属**：线索转化出的客户可能没有负责人，后续合同会被拦。建议转化弹窗里让操作人选择 "归给自己 / 进公海"。

## 七、需要主人拍板的业务取舍（K1 已拍板，其余待拍板）

### 第 3 组：打样已批准后怎么终止？



* A（推荐）：新增 `terminated`（已终止）状态，需主管确认并填原因；已制作 / 已寄送的事实保留、费用照记，不删单。

* B：只允许 "已批准但未制作" 时终止；已制作后只能开修订版或等流程走完。

* C：不新增状态，维持现状。

### 第 4 组：非客户原因的终止 + 完成口径



* 4.1 报价已发送、我方不做了：A（推荐）新增「报价关闭」动作，填原因、留痕，不改客户结果字段；B 只允许用 "客户拒绝 / 过期"；C 不做。

* 4.2 订单草稿：A（推荐）新增「作废草稿」软删，本人 / 主管可操作；B 不做。

* 4.3 订单仍有未收款时能否点「已完成」：A 允许但必须二次确认并写原因；B 必须收齐才能完成；C 维持现状。
