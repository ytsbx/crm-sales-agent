## 一、补充项检查结果

### B03-19｜P2｜价格/成本导入的单行失败与整批提交失败把底层异常字符串直接返回前端

- **位置**：
  - 单行失败：`backend/app/modules/pricing/io_router.py:279-282`（价格规则）、`492-495`（客户专属价）、`744-747`（成本）
  - 整批提交失败：`backend/app/core/importing.py:686-692`
- **触发条件**：导入行触发数据库约束错误（唯一键、外键、列溢出）、类型错误，或整批 `commit` 失败。
- **后果**：`report.failed_row(..., f"写入失败：{str(exc)[:160]}")` 把 `IntegrityError`/`DataError` 的原文（常见包含表名、列名、约束名、SQL 片段）直接显示在导入报告；整批提交失败也把 `str(exc)[:120]` 放进 500 文案。用户/前端能看到内部库结构，属于错误信息泄露；同时 `except Exception` 把编程错误也降级成“某行写入失败”，服务端没有 `logger.exception`，排查看不到堆栈。
- **证据代码**：
  ```python
  except Exception as exc:  # 单行失败不影响其它行
      report.failed_row(index, code, f"写入失败：{str(exc)[:160]}")
  ...
  except Exception as exc:
      await session.rollback()
      raise AppError(ErrorCode.SYSTEM_ERROR,
          f"导入提交失败，本次没有任何数据写入（{str(exc)[:120]}），请重试或联系管理员", 500)
  ```
- **建议**：对用户只返回稳定文案（“第 N 行写入失败，请检查 SKU/区间/生效日”或“导入提交失败，未写入”），原始异常写服务端日志并带行号/文件名/操作人，不返回前端；如果要在报告里给细节，只给可公开的业务原因（重复、越界、外键对象不存在）。
- **测试覆盖**：未覆盖。`backend/tests` 没有价格规则/客户专属价/成本导入的失败报文测试；现有导入测试集中在企微客户导入，不覆盖这里的 `str(exc)` 出口。

### B03-20｜P2｜价格/成本批量导入审计只记文件和计数，不记每行改了哪个价、旧值是什么

- **位置**：`backend/app/core/importing.py:668-683`（`action="import"` 的 `after`）；调用方 `pricing/io_router.py:284、497、749`
- **触发条件**：正式导入价格规则、客户专属价或 SKU 成本。
- **后果**：审计只有 `file/file_sha256/created/updated/skipped/failed/failed_rows`，没有 `sku_id/sku_code`、价格/成本字段、生效日、旧值、更新前后差异。导入是批量改价的关键钱操作；文件本身不保证长期保留，事后无法从审计复算“哪些 SKU 从多少改到多少”。预览令牌的 `plan/baselines` 只在请求内使用，不落审计。
- **证据代码**：
  ```python
  after={
      "file": file_name,
      "file_sha256": file_sha256,
      "created": report.created_count,
      "updated": report.updated_count,
      "skipped": report.skipped_count,
      "failed": report.failed_count,
      "failed_rows": sorted(report.failure_rows()),
  }
  ```
- **建议**：`report` 里保存每行的业务快照（SKU 编码、价格/成本、生效日、旧值/新值、状态），审计写摘要 + 可回查的快照 id（或把原文件存入受控文件表并关联 file_id）；至少对 `updated` 行逐行记录 `before/after` 金额，金额用 Decimal 字符串。
- **测试覆盖**：未覆盖。没有导入审计断言；`test_pricing_history_filters.py` 只测历史查询过滤，不测导入审计内容。

### B03-21｜P2｜物流试算/对比的 quantity、weight/volume override 没有上限，超大值会让 Numeric 列溢出成 500

- **位置**：`backend/app/modules/pricing/logistics_schema.py:11-25`（`quantity`、`weight_override`、`volume_override` 只有 `Decimal`，无 `gt/max_digits/decimal_places`）；`pricing/logistics.py:435-440` 只拦 `<=0`；落库 `pricing/logistics.py:550-575`；列宽 `pricing/model.py:199-208`
- **触发条件**：调用 `/logistics/calculate` 或 `/logistics/compare`，`quantity=1e100`（或覆盖重量/体积 1e100），并 `save=true`；或 quantity 小数位远超 3 位。
- **后果**：`quantity <= 0` 的闸门只拦负数和 0，不拦超大值；`compute_weight_and_volume` 会算出巨大重量/体积/金额，`save_quote` 再写入 `Numeric(16,3)/Numeric(16,4)/Numeric(16,2)` 列，数据库溢出抛 `DataError`，接口 500。试算不保存时也可能因 `float()` 溢出/JSON 序列化失败。不是金额算错，而是非法输入打到 500，且可能留下半条失败日志。
- **证据代码**：
  ```python
  class LogisticsCalculateRequest(BaseModel):
      quantity: Decimal = Decimal(1)          # 没有 max_digits/decimal_places
      weight_override: Decimal | None = None  # 没有上限
      volume_override: Decimal | None = None
  ...
  if quantity <= 0:
      raise AppError(... "数量必须大于 0" ...)
  # 没有 quantity > Numeric(16,3) 上限的校验
  ```
- **建议**：在 schema 层给 `quantity` 加 `gt=0, max_digits=16, decimal_places=3`，给 `weight_override/volume_override` 加 `gt=0, max_digits=16, decimal_places=4`；`expected_amount` 加 `max_digits=16, decimal_places=2`。服务层保留现有 <=0 闸门作为第二道。
- **测试覆盖**：未覆盖。`backend/tests/test_logistics_quote.py` 只测体积/重量取大、最低收费和零最低收费，没有超大数量/覆盖值/小数位超限用例。

### B03-22｜P3｜导入逐行 `except Exception` 把编程错误降级成“该行失败”，没有服务端日志/告警

- **位置**：`backend/app/modules/pricing/io_router.py:281-282、494-495、746-747`
- **触发条件**：导入代码自身出现 `AttributeError/TypeError/KeyError` 等非业务异常（例如某行字段结构变化、ORM 状态异常）。
- **后果**：异常被 `except Exception` 捕获后只写进 `report.failed_row`，不 `raise`、不 `logger.exception`；整批其他行继续提交。结果可能是“99 行成功、1 行失败”的正常报告，但实际上有一个代码缺陷被掩盖；用户看到的是“写入失败：...”而没有可复现堆栈，开发侧也没有告警。
- **建议**：区分“预期的数据库/业务异常”和“未预期异常”：对 `IntegrityError/DataError/AppError` 走行失败并给业务文案；其他异常记录 `logger.exception`（带 row/file/module/operator，不带金额和客户敏感信息）后继续或整批失败，按业务取舍决定。
- **测试覆盖**：未覆盖。没有导入的故障注入用例。

## 二、补充项“没发现问题”的结论

- **负数/0/小数位**：`pricing/schema.py` 的成本/价格/权限比例仍有 `ge/gt/max_digits/decimal_places`；`logistics.prepare` 已补 `quantity/weight/volume <=0` 闸门（本块复核确认）。新增问题只在上限/超大值，见 B03-21。
- **事务边界**：导入“逐行 SAVEPOINT + 整批一个事务 + 预览整体 rollback + 提交失败 rollback”是成立的，单行失败不会把整批带进失败态；`finalize` 提交失败明确不返回成功统计。没有发现“导入一半提交、另一半丢”的半成品路径。
- **异常/日志**：除 B03-19/B03-22 的导入异常出口外，物流/定价/成本正常路径没有发现吞异常后继续成功的分支；`pricing/service.py:851` 把运费估算的 `AppError` 转成“请手工填写”的可见警告，不是静默成功（该点与 B02 补充重复，不单列）。
- **审计**：页面侧成本/价格规则/客户专属价/价格权限/运费费率的增改删都有审计（字段完整性问题见 B02-14）；导入侧审计只有汇总，见 B03-20。
