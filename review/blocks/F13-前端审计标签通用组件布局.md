### F13-04（P2）权限目录失败时选择器显示“已选 0 / 0”，且可能静默丢权限

- 文件:行号：`frontend/src/modules/settings/SettingsPage.tsx:2417-2421`、`frontend/src/shared/components/PermissionPicker.tsx:112-196`
- 触发条件：编辑角色时 `/users/permissions` 请求失败/超时；或后端返回的权限目录不完整（例如新权限尚未部署、接口只返回部分 resource）。
- 后果：`options` 为空或缺少条目，选择器显示“已选 0 / 0”且没有错误/重试，管理员会误以为该角色没有任何权限；`toggle` 以 `options.filter(...)` 回写，目录不完整时会把不在当前 `options` 里的已选 code 静默删掉，保存后角色权限被缩减。
- 证据代码：

```tsx

  loading={permissionsQuery.isLoading}
  value={roleForm.permission_codes}
  onChange={(codes) => setRoleForm({ ...roleForm, permission_codes: codes })}
  options={(permissionsQuery.data ?? []).map((perm) => ({ ... }))}
/>
```

```tsx
const toggle = (code: string, checked: boolean) => {
  const next = new Set(value)
  if (checked) next.add(code)
  else next.delete(code)
  onChange(options.filter((option) => next.has(option.code)).map((option) => option.code))

```

- 建议：把 `permissionsQuery.isError` 和 `refetch` 传进选择器；目录未成功加载时禁止保存/勾选，并显示“权限目录读取失败”；回写时保留 `value` 中不在 `options` 的 code（或显式提示“有 N 个权限未加载”），不要用 `filter` 静默丢弃。
- 测试覆盖：部分覆盖。`ops/check_permission_groups.py` 只检查分组覆盖，不测失败态、部分目录和保存丢 code；无前端权限选择器测试。

## 五、正向确认

- `ops/blocked_hint.test.mjs` 覆盖了 `blockedReasons` 的空值、空白、坏数据、重复原因和 `blockedToastText` 的“另有 N 条”，本块没有发现新的禁用提示逻辑缺陷。

- `PaymentVoucherControl` 的删除入口受 `payment:manage` 且仅 `pending` 状态约束；后端删除凭证走 `inspect_file_usage`，有受保护引用时拒绝、共享时只解绑，并写 `remove_voucher` 审计。
- `PermissionPicker` 的 `PERMISSION_SECTIONS` 对未知 resource 有“其他权限”兜底，`ops/check_permission_groups.py` 能检查后端 resource 是否都有中文名和分组。
- `MaskedContact` 的 `masked` 分支对后端已脱敏值只显示星号、不提供“点开变完整”的假入口；打码算法本身没有把完整号码拼回去。
