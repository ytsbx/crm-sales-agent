## 一、补充项检查结果

### B02-14｜P2｜价格权限修改、价格规则停用、客户专属价删除的审计缺 `before`，无法复算价格权限/生效价变化

- **位置**：
  - 价格权限修改：`backend/app/modules/pricing/router.py:970-984`
  - 价格规则停用：`pricing/router.py:632-639`
  - 客户专属价删除：`pricing/router.py:918-926`
- **触发条件**：管理员修改某角色的 `minimum_margin/discount_limit/can_approve`；或停用一条正在生效的价格规则；或删除某客户的专属价。
- **后果**：这些操作都会改变“谁能批什么价/这个客户按什么价”，但审计只写 `after` 或只写 `action + id`：
  ```python
  # update_price_permission
  after=svc.serialize_permission(permission, role.name)   # 没有 before
  # disable_price_rule
  action="disable", business_type="price_rule", business_id=rule.id   # 没有 before/after
  # delete_customer_price_rule
  action="delete", business_type="customer_price_rule", business_id=rule_id   # before 未写
  ```
  事后只能看到“改过/停过/删过”，看不到旧的利润率、折扣上限、审批权，也看不到被删的专属价金额、数量区间、有效期。价格权限被放宽或专属价被删后，历史报价为什么突然能过审批/为什么改用通用价，审计无法回答。
- **建议**：三处都补 `before`（完整的序列化结果）和 `after`（修改/停用/删除后的状态）；金额/比例用 Decimal 字符串。停用规则可写 `before={"status":"active", ...}`、`after={"status":"disabled"}`；删除客户专属价把原规则快照写入 `before`。
- **测试覆盖**：未覆盖。`backend/tests/test_pricing_history_filters.py`、`test_pricing_history_scope.py` 只测历史记录的可见性/过滤，没有断言 `before` 字段；`test_cosign_permission.py` 测会签权限判断，不测价格权限修改审计。

### B02-15｜P2｜客户接受/拒绝报价的审计只记版本号，不记金额/币种，接受后改费会让审计无法复算

- **位置**：`backend/app/modules/quote/lifecycle.py:37-40`（`_record` 统一审计）、`150-151`（accept）、`164-166`（decline）
- **触发条件**：客户接受或拒绝报价；尤其是接受后又被 B02-01 的“改运费”路径改了总额。
- **后果**：`_record` 的审计 `after` 固定是 `{"version_id", "version_no", ...after}`：
  ```python
  after={"version_id": version.id, "version_no": version.version_no, **after}
  ```
  `accept` 传 `after={}`，`decline` 只多一个 `reason`。没有 `total_amount`、`currency`、`subtotal/charge/discount`。接受后版本总额仍可被改（B02-01），审计里又没有“客户接受时是多少钱”，事后无法证明客户到底接受了哪个金额；拒绝同理，无法复算被拒绝的报价金额。
- **建议**：`_record` 增加 `total_amount/currency/subtotal_amount/charge_amount/discount_amount`，在 `accept_version/decline_version` 写状态前取当时的 `version.total_amount` 快照；金额用 `format(Decimal, "f")`。如果接受后允许改费，接受审计的金额就是唯一能证明“客户同意的是旧金额”的证据，必须落。
- **测试覆盖**：未覆盖。`backend/tests/test_quote_cost_gate.py:56` 只测 `mark_version_sent` 的成本闸门；`test_quote_doc_freeze.py` 测文档冻结，不测 accept/decline 审计；没有断言 `AuditLog.after_data` 含金额的用例。

### B02-16｜P3｜`_session_dialect` 宽泛吞异常后返回空串，会静默跳过价格规则的 advisory 锁

- **位置**：`backend/app/modules/pricing/service.py:506-515`；调用方 `lock_sku_price_rules` 在 `518` 起按 dialect 决定是否加锁
- **触发条件**：`session.get_bind()` 抛异常（连接/绑定异常、测试替身未实现、事务已失效），`_session_dialect()` 返回 `""`。
- **后果**：`lock_sku_price_rules` 把空串当“非 PostgreSQL”，跳过 `pg_advisory_xact_lock`；价格规则的“先查区间冲突再写”重新变成无锁并发，两个请求可各写一条重叠规则，取价时静默二选一。正常情况下 `get_bind` 不该失败，但这正是“异常被吞掉后继续当成功”的路径。
- **证据代码**：
  ```python
  try:
      return session.get_bind().dialect.name
  except Exception:  # noqa: BLE001
      return ""
  ```
- **建议**：只捕获明确的 `AttributeError/InvalidRequestError`，或让异常上抛；如果确实要降级，至少返回一个显式的 `"unknown"` 并让 `lock_sku_price_rules` 在未知方言时拒绝写价格规则/报 503，不能静默跳过锁。
- **测试覆盖**：未覆盖。测试都跑 SQLite，`_session_dialect` 正常返回 `"sqlite"`，不会触发 `get_bind` 异常分支；没有故障注入用例。

### B02-17｜P3｜创建报价失败时 `release` 自身再失败会掩盖原始异常，并可能留下占位

- **位置**：`backend/app/modules/quote/router.py:323-329`
- **触发条件**：`create_quote` 因参数/DB 错误抛异常，进入 `except Exception`；`await idempotency.release(session, reservation)` 又失败（连接已坏、事务状态不可用、释放语句冲突）。
- **后果**：`release` 的异常替换了原始异常，前端看到的是“释放占位失败”而不是真正的业务错误；原始错误原因丢失，排查困难。如果 `release` 没成功，`request_keys` 里还留着占位，用户带同一把键改内容重试可能被判定“同键不同内容”。
- **证据代码**：
  ```python
  except Exception:
      if reservation is not None:
          await idempotency.release(session, reservation)
      raise
  ```
- **建议**：`release` 单独 `try/except`，失败时记录原始异常和 release 异常（可用 `logger.exception`，不要打印金额/客户敏感字段），然后 `raise` 原始异常；或者把占位释放放到独立事务/后台清理，避免在已坏的事务里再写。
- **测试覆盖**：部分覆盖。`backend/tests/test_quote_request_idempotency.py` 覆盖“业务异常时释放占位成功”，没有覆盖“释放本身失败”的故障注入。

## 二、补充项“没发现问题”的结论

- **负数/0/超大值/小数位**：`pricing/schema.py` 的成本/价格/数量/运费/汇率/权限比例都带 `ge/gt/le/max_digits/decimal_places`；`PricingSimulation` 对 `candidates/margins` 逐项校验有限、16 位、4 位小数，堵住了 `1e1000`。本补充没有发现新的边界缺口。`QuoteClone.owner_id` 为 0/负数会生成“无主报价”，但这属于 B02-02 的负责人校验问题，不重复编号。
- **事务边界**：报价创建/改价/费用/审批/发送/接受/拒绝都是“写业务 + 写审计/事件 + 一次 commit”；价格规则/成本/客户价/运费费率也是“flush + 审计 + commit”。未发现“报价建了版本没建”的半成品路径。B02-16/B02-17 是异常降级路径，不是正常事务边界。
- **异常/错误信息/日志**：`quote/router.py:997` 的 `logger.exception` 只带 `quote_id`，traceback 不含金额/客户字段；`pricing/service.py:851` 把运费估算的 `AppError` 转成“请手工填写”的可见警告，不是静默成功；未发现把 SQL/堆栈直接返回前端。B02-16/B02-17 是“吞异常/掩盖原始异常”的边界。
- **审计（已有）**：报价创建、更新、删除、复制、成本刷新、价格刷新、版本/明细/费用、提交/撤回审批、发送、接受、拒绝、邮件登记都有审计；价格规则/成本/客户价/运费费率也有审计。新增问题只在“审计字段够不够复算”，不是“完全没写”。
