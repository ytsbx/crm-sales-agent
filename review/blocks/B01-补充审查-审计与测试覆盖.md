## 一、补充检查结果（只列新增发现）

### B01-10｜P2｜改价/整批替换明细的审计字段不完整，数量、成本、物流成本变化无法从审计复算

- **位置**：
  - 单条改价：`backend/app/modules/quote/router.py:1369-1377`
  - 整批替换：`backend/app/modules/quote/router.py:1235-1243`
  - 删除明细：`router.py:1412-1421`（`before` 是完整快照，`after` 只有总额）
- **触发条件**：用户只改 `quantity`、`unit_cost`、`logistics_cost`，或走 `POST /quote-versions/{id}/items/batch` 整批替换；也可能只改 `remark` 走“备注分支”（`router.py:1306-1318`）。
- **后果**：`update_item` 的审计 `before/after` 只有 `item_id` 和 `quoted_price`：
  ```python
  before={"item_id": item.id, "quoted_price": old_price},
  after={"item_id": item.id, "quoted_price": float(item.quoted_price)},
  ```
  数量、成本、物流成本、行金额、版本合计都没有进审计。`set_items` 更少，只写 `after={"count": len(items)}`。事后只能看到“改过这条明细”，无法复算“从多少数量/成本改到多少、总额为什么变”，也无法判断是否触发过底价/审批。关键钱操作的审计存在，但不足以复原金额变化。
- **建议**：`before/after` 统一记录 `quantity/quoted_price/unit_cost/logistics_cost/line_amount/price_source` 以及版本 `subtotal/charge/discount/total`；金额用 `format(Decimal, "f")` 字符串，不转 float。`set_items` 至少记录变更前后的 item 数量、每行 `sku_id/quantity/quoted_price/unit_cost` 摘要与版本总额，或记录一个可回查的快照 id。
- **测试覆盖**：未覆盖审计内容。`backend/tests/test_quote_cost_gate.py:542` 调用 `update_item` 只断言价格/成本/总额，没有断言审计字段；`test_quote_request_idempotency.py` 把 `write_audit` 替换成 `AsyncMock()`，更不会检查内容。

### B01-11｜P3｜报价审计金额用 float 写入，大额/四位单价时审计值与真实 Decimal 不一致

- **位置**：`backend/app/modules/quote/router.py:1376`、`1419`、`2004`；`backend/app/modules/quote/service.py` 序列化里的 `_f`
- **触发条件**：报价接近 `Numeric(16,2)` 上限，或单价/成本是 4 位小数；审计 `after` 里写 `float(...)`。
- **后果**：审计 JSON 落的是二进制浮点近似值，和数据库里的 Decimal 可能差 1 分或更多；出事后拿审计复算，会和真实金额对不上。与 B01-02 的“出参 float”同源，但审计是留痕证据，影响更直接。
- **证据代码**：
  ```python
  after={"item_id": item.id, "quoted_price": float(item.quoted_price)},
  ...
  after={"quote_version_id": version.id, "total_amount": float(version.total_amount)},
  ```
- **建议**：审计金额统一 `str(Decimal)`（必要时 `format(..., "f")`），不要 `float()`；前端展示再自行格式化。
- **测试覆盖**：未覆盖。`test_quote_pdf_precision.py` 测的是 PDF 精度，不是审计 JSON；`test_quote_cost_gate.py` 断言的是接口返回值。

## 二、补充项的“没发现问题”结论

- **负数/0/超大值/小数位**：`QuoteItemInput/Update` 的 `quantity gt=0/decimal_places=3`、`quoted_price gt=0/decimal_places=4`、`unit_cost/logistics_cost ge=0/decimal_places=4`，`QuoteChargeInput/Update` 的 `amount ge=0/max_digits=16/decimal_places=2`，与库列精度对齐；没有发现“新增严、编辑松”的旁路。显式 0 运费是合法业务值，不算漏洞。
- **事务边界**：`create_quote` 用 `request_keys` 预占，异常时 `release`；`update_item` 先锁版本、再 `reload_locked_child`，改价与审计同一事务；`set_items` 删除/新增/重算/审计同一事务。未发现“订单建了明细没建”这类半成品路径（报价侧）。
- **异常吞掉/信息泄露/日志敏感**：`quote/service.py` 只在 `create_version` 捕获 `IntegrityError` 并转 409；未发现 `except Exception: pass` 后继续当成功。B01-04 的 `probe` 日志仍会打印 `prev_floor`（底价派生值），原报告已记 P3，补充复核维持。
- **测试覆盖（原发现）**：B01-01 的“float 边界”没有专门用例（现有 `test_config_rule_conflicts.py` 测的是规则合并，不是金额边界）；B01-02 有 `test_quote_cost_gate.py:159-179` 的 `*_exact` 断言；B01-03 没有“恰好半分/半厘”的 tie 用例。原报告结论不变，测试覆盖栏在本补充里补齐。
