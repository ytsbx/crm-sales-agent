### B21-01 P2 打样费用/运费/数量/积分出口仍走 float

**位置**
- `backend/app/modules/sample/service.py:34-35`（`_f = round(float(value), 4)`）
- `backend/app/modules/sample/service.py:77、85`（明细原数量/本次数量）
- `backend/app/modules/sample/service.py:100`（寄样运费）
- `backend/app/modules/sample/service.py:153、156-160`（预计工时、积分）
- `backend/app/modules/sample/service.py:179`（打样费用）

**触发条件**：打样费用有分位、运费有分位、数量有 3 位小数，或工时×10 产生 2 位小数；列表/详情/导出申请单读取这些字段。

**后果**：`sample_fee`、`shipping_fee` 是钱，`quantity` 是打样数量，`craft_points` 是计费依据；全部先转 float 再 round，前端再做汇总/导出时可能与 Decimal 原值出现尾差。`test_sample_application_form.py` 的 `_total_quantity` 用 Decimal，但接口 `/samples` 返回的 `quantity` 已经是 float，导出和列表可能对不上。与 B20-07、B19-03 同类，但这是打样费用/运费入口，之前没覆盖。

**证据代码**
```python
def _f(value) -> float | None:
    return None if value is None else round(float(value), 4)
...
"original_quantity": _f(item.original_quantity),
"quantity": _f(item.quantity),
...
"shipping_fee": _f(shipment.shipping_fee),
...
"sample_fee": _f(request.sample_fee),
```

**建议**：金额/数量响应增加 `*_exact`（字符串或 Decimal 序列化），原 float 字段只做展示；导出申请单/汇总一律用 exact。`craft_points` 用 Decimal 计算后再序列化，不要先 float。

**测试覆盖**：未覆盖。`test_sample_sources.py:34-42` 只断言整数 10000/2；`test_sample_application_form.py` 只测 `_total_quantity` 的 Decimal 文本，没有调 `/samples` 序列化并断言 2/3 位小数精度。

**后果**：这些字段在 schema 层没有长度上限，Pydantic 放行后到 `session.flush()`/commit 才撞 PostgreSQL `value too long for type character varying(N)`，接口 500。驳回理由超长时审批动作失败；寄样信息超长时寄样登记失败；用户看到的是服务器错误，不是“哪个字段太长”。模型列宽明确，schema 却没跟，属于输入边界缺口。

**证据代码**
```python
class SampleApprove(BaseModel):
    approved: bool = True
    reject_reason: str | None = None
class SampleConfirm(BaseModel):
    accepted: bool
    remark: str | None = None
class SampleShip(BaseModel):
    carrier: str | None = None
    tracking_no: str | None = None
```
对照 `model.py`：
```python
reject_reason: Mapped[str | None] = mapped_column(String(255), nullable=True)
confirm_remark: Mapped[str | None] = mapped_column(String(255), nullable=True)
carrier: Mapped[str | None] = mapped_column(String(64), nullable=True)
tracking_no: Mapped[str | None] = mapped_column(String(64), nullable=True)
```

**建议**：这些字段全部加 `Field(max_length=...)`，与模型列宽一致；`SampleItemInput.item_name` 加 200；如果业务允许长备注，改成 Text 列并同步 schema，不要靠 DB 报错。补 `test_sample_schema_lengths` 覆盖 201/256/65 字符。

**测试覆盖**：未覆盖。`test_sample_application_form.py` 只测申请表选项/工时/图片；`test_sample_sources.py` 只测数量/重复明细；`test_sample_delete_policy.py` 不测驳回/确认/寄样入参。

### B21-03 P2 产品/SKU 导入把底层异常原文回显到失败清单

**位置**
- `backend/app/modules/product/io_router.py:179-180`（产品导入 `except Exception`）
- `backend/app/modules/product/io_router.py:421-422`（SKU 导入 `except Exception`）

**触发条件**：某行通过前置字段校验，但写库时触发数据库异常（例如超长、约束、连接/序列化错误），`Product(...)`/`Sku(...)` flush 抛非 `RowSkipped/RowRejected` 异常。

**后果**：`report.failed_row(index, name, f"写入失败：{str(exc)[:160]}")` 会把底层异常文本直接返回给导入用户。PostgreSQL 的错误可能带表名/列名/约束名/SQL 片段；如果异常链里有连接串或驱动细节，也会被截断后暴露。用户只需要知道“这一行写入失败、哪几个字段有问题”，不需要数据库方言错误。与 B13-05、B19-04 同类，但这是产品/SKU 导入入口，之前没覆盖。

**证据代码**
```python
except Exception as exc:
    report.failed_row(index, name, f"写入失败：{str(exc)[:160]}")
```
```python
except Exception as exc:  # 单行失败不影响其它行
    report.failed_row(index, code or product_name, f"写入失败：{str(exc)[:160]}")
```

**建议**：保留原始异常给日志（带 request id/行号），对用户只返回“这一行写入失败，请检查字段长度/重复/数据库约束”，必要时按 `IntegrityError`/`DataError` 分类给业务提示；不要拼接 `str(exc)`。同时把 `RowRejected` 与真正的系统异常分开，系统异常应让整批失败或明确“服务器错误”，不要伪装成行级业务失败。

**测试覆盖**：未覆盖。`test_seventh_round_imports.py` 测的是字段解析、NaN/负数/整数截断、preview，不测 DB 异常回显；没有模拟 flush 抛 `IntegrityError` 并断言错误文案不含表名/列名。

### B21-04 P2 新品洞察价格假设/评审快照 Decimal→float

**位置**
- `backend/app/modules/product_insight/router.py:104-106`（`price_assumption` 序列化 float）
- `backend/app/modules/product_insight/router.py:140-148`（`_content_snapshot` Decimal→float）
- `backend/app/modules/product_insight/router.py:760`（转换描述 `float(row.price_assumption)`)
- `backend/app/modules/product_insight/model.py:66`（`Numeric(16,2)`）

**触发条件**：价格假设有分位（例如 `12.34`），列表/详情/逐轮评审记录/转需求描述读取它。

**后果**：价格假设是“未确认的内部参考”，不进入价格规则，但它会被评审人用来判断方向、被转成需求描述；float 序列化/快照会让同一笔假设在列表、轮次快照、需求描述里出现不同尾数（例如 `12.340000000000001`），事后对“当时假设是多少”无法逐位复算。属于金额精度/审计快照问题，不是正式报价，故列 P2 而非 P1。

**证据代码**
```python
"price_assumption": (
    float(row.price_assumption) if row.price_assumption is not None else None
),
...
```
