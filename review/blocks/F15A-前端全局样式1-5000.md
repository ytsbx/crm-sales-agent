## 二、发现清单

### F15A-01（P2）全站无 `href` 的操作链接键盘无法聚焦，CSS 只补了鼠标手型

- 文件:行号：`frontend/src/index.css:200-218`
- 触发条件：用户只用键盘/读屏，Tab 到表格「操作」列或详情页的下载、恢复、详情、编辑等入口。
- 后果：项目里大量操作写成 `<a>` + `onClick`，没有 `href`。浏览器对无 `href` 的 `<a>` 不提供默认 Tab 焦点，也不响应 Enter/Space；CSS 只能改 `cursor` 和颜色，补不出可聚焦语义。键盘用户会直接跳过这些操作，下载凭证、恢复客户、查看详情等关键动作无法完成。
- 证据代码：

```css
/* index.css:200-218 */
a:not([href]) {
  cursor: pointer;
  color: var(--crm-primary);
}
```

```text
frontend/src 下 <a 标签：101 处
带 href：2 处
带 onClick：35 处
带 role：0 处
带 tabIndex：0 处
```

具体调用点如 `modules/recycle/RecycleBinPage.tsx:743` 的「恢复」、`modules/common/PaymentVoucherControl.tsx:56-66` 的凭证下载、`modules/contract/DocumentsPage.tsx:753` 的「详情」，都是无 `href` 的 `<a onClick>`。

- 建议：把这些入口统一换成 Semi `Button`/`Link` 或原生 `button`；确实要保留 `<a>` 时补 `role="button" tabIndex={0}`，并处理 `Enter`/`Space`。CSS 层不要继续把“无 href 的 a”当成按钮用。
- 测试覆盖：未覆盖。没有前端可访问性测试；`ops` 下也没有针对无 href 链接的静态检查。

### F15A-02（P2）全站表格单元格强制单行省略，固定宽度的金额列会截断超大金额且没有完整值兜底

- 文件:行号：`frontend/src/index.css:2063-2070`、`2299-2322`、`4962-4967`；调用证据 `frontend/src/modules/order/OrderListPage.tsx:253-265`
- 触发条件：订单/回款/应收等表格出现位数较多的金额，例如 `¥12,345,678.90`；或窄屏 108px 的 compact 金额列；或浏览器放大字体。
- 后果：所有 `.semi-table-row-cell` 被 `white-space:nowrap + overflow:hidden + text-overflow:ellipsis` 强制单行裁切。订单金额列宽 124px（compact 108px），扣掉单元格左右内边距后可用宽度更小；而该列 `render` 直接返回 `formatMoney(...)` 字符串，没有 `title` 或展开入口。金额被省略号截断后，用户看不到完整数字，可能按错误量级判断回款/应收。合计块的 `.qst-amount` 则是 `nowrap` 但不 `overflow:hidden`，超大金额会直接撑出卡片，属于同一条“超大值没有兜底”的两端表现。
- 证据代码：

```css
/* index.css:2063-2070 */
.semi-table-tbody .semi-table-row-cell {
  white-space: nowrap;
  overflow: hidden;
  text-overflow: ellipsis;
}

/* index.css:2299-2322 */
.payments-table .semi-table-row-head,
.payments-table .semi-table-row-cell {
  overflow: hidden;
}
.orders-table .semi-table-row-cell {
  overflow: hidden;
}

/* index.css:4962-4967 */
.qst-amount {
  font-size: 18px;
  white-space: nowrap;
}
```

```tsx
// modules/order/OrderListPage.tsx:253-265
{
  title: '订单金额',
  dataIndex: 'total_amount',
  className: 'cell-right',
  width: compact ? 108 : 124,
  render: (v: number, record: Order) =>
    formatMoney(toTwoDecimals(record.total_amount_exact ?? v), record.currency),
}
```

- 建议：金额列不要套全站省略号规则；给金额单元格 `white-space:nowrap` 但不 `overflow:hidden`，或列上设置 `ellipsis` 并同时提供 `title`/点击查看完整金额。更好的做法是金额列保底最小宽度，表格容器横向滚动，而不是把数字裁掉。`.qst-amount` 增加 `overflow-wrap:anywhere` 或 `min-width:0` 的响应式降字号。
- 测试覆盖：未覆盖。没有金额列在 1024/1280/200% 缩放下的渲染测试，也没有“超大金额不被截断”的快照/视觉测试。

### F15A-03（P2）全站表格强制居中，数值列必须逐个挂 `.cell-right`；What-if 对照表漏挂，金额/数量仍被居中

- 测试覆盖：未覆盖。没有“金额列必须右对齐”的组件测试，也没有对 `align:'right'` 列实际计算样式做快照。

### F15A-04（P3）46 处 `:has()` 承载布局/隐藏逻辑，旧浏览器会静默失效

- 文件:行号：`frontend/src/index.css:245、785-788、1943、2824、3838、4362、4367、4370、4375、4386、4579-4581`
- 触发条件：使用不支持 `:has()` 的浏览器（Chrome 105 以下、Safari 15.4 以下、Firefox 121 以下）或企业内旧内核。
- 后果：选择器整条被浏览器丢弃，不报错。具体表现为：单卡页面不再拉满高度、空表格横向滚动条重新出现、`blocked-hint-click` 禁用光标不生效、订单详情按钮区的受阻原因块不被隐藏、确认弹窗/主数据预览的自定义内边距和 footer 不生效。都是视觉/布局问题，不影响金额和权限，但会让旧环境页面显得错位。
- 证据代码：

```css
/* index.css:245 */
.page-container:not(:has(.card-block ~ .card-block)) > .card-block {
  flex: 1 1 auto;
}

/* index.css:785-788 */
.semi-table-wrapper:has(.semi-table-placeholder) .semi-table-header,
.semi-table-wrapper:has(.semi-table-placeholder) .semi-table-body {
  overflow-x: hidden;
}
```

- 建议：确认目标浏览器矩阵；如果存在旧内核，给 `:has()` 承载的关键规则补 `@supports selector(:has(*))` 的降级，或改成组件层加 class。纯装饰规则可以保留。
- 测试覆盖：未覆盖。没有浏览器矩阵/旧内核回归测试。

### F15A-T01（待确认）toast 固定 `top:84px` 是否在 768 断点压住页签栏

- 文件:行号：`frontend/src/index.css:37-41`
