### F15B-01（P2）窄屏直接隐藏金额列，1024 下看不到“已收/未收/已分配/待分配”

- 文件:行号：`frontend/src/index.css:5241-5246、5282-5286`；调用证据 `frontend/src/modules/order/OrderDetailPage.tsx:871-872、1433-1435、1659-1672`
- 触发条件：视口宽度 `< 1200px`（常见 1024 笔记本/分屏），打开订单详情的「应收计划」「回款记录」页签。
- 后果：`.col-hide-narrow` 用 `display:none !important` 把整列移除，不是横向滚动、也不是折叠。应收计划里“已收”“未收”两列同时消失，只剩“应收金额 + 状态”；回款记录里“已分配”“待分配”消失，只剩“整笔到账”。用户无法判断这笔应收还差多少、这笔回款还有多少没分配，容易把“状态=已确认”误当成“已收清”。跟进页签还会隐藏“记录时约定”，窄屏看不到下次约定时间。
- 证据代码：

```css
/* index.css:5241-5246 */
@media (max-width: 1199px) {
  .followup-col-due,
  .followup-col-minor {
    display: none !important;
  }
}

/* index.css:5282-5286 */
@media (max-width: 1199px) {
  .col-hide-narrow {
    display: none !important;
  }
}
```

```tsx
// modules/order/OrderDetailPage.tsx:871-872

{ title: '待分配', dataIndex: 'unallocated_amount', width: 108, className: 'cell-right col-hide-narrow', ... },
```

- 建议：金额列不要用 `display:none` 让位。改成表格容器横向滚动，或把“已收/未收”合并成一格两行、把“已分配/待分配”压在“整笔到账”下面。若业务确认“窄屏可以牺牲金额列”，需要人工拍板并在页面明确提示“窄屏已隐藏金额列”。
- 测试覆盖：未覆盖。没有 1024 宽度下订单详情金额列可见性的测试。

### F15B-02（P2）弹窗里的错误态输入框被自定义样式压成普通灰底/蓝边，校验失败的红框消失

### F15B-03（P2）禁用的实心主按钮仍显示蓝字白底，看起来可以点

### F15B-04（P3）分析页商机漏斗/台阶用固定宽度，320 宽会横向溢出

- 文件:行号：`frontend/src/index.css:5499-5513、7070-7077、7160-7163`
- 触发条件：手机 320–360 宽度打开数据分析「商机转化」；或浏览器 200% 缩放。
- 后果：`.deal-flow` 固定 `flex: 0 0 404px`，父级 `flex-wrap` 只把摘要卡换行，不会把 404px 的流程缩窄；320 宽页面去掉卡片左右 20px 内边距后只有约 280px，流程条直接横向溢出。四列清单 `.deal-table-head/.deal-table-row` 在 1180 以下固定为 `1fr 72px 96px 96px + 36px gap`，固定部分已 300px，320 宽同样顶出容器。页面没有横向滚动壳，表现为右侧被裁或整页横向滚动。
- 证据代码：

```css
/* index.css:5499-5513 */
.deal-flow {
  flex: 0 0 404px;
  min-width: 0;
}

/* index.css:7070-7077 */
.deal-table-head,
.deal-table-row {
  grid-template-columns: minmax(0, 1.5fr) minmax(0, 1fr) minmax(0, 1fr) minmax(0, 1fr);
}
/* index.css:7160-7163 */
@media (max-width: 1180px) {
  .deal-table-head, .deal-table-row { grid-template-columns: minmax(0, 1fr) 72px 96px 96px; gap: 12px; }
}
```

- 建议：给 `deal-flow` 加 `@media (max-width: 560px) { flex-basis: 100%; }`，四列清单在 560 以下改成两列或单列卡片；或把整个图表放进横向滚动壳并给 `min-width`。
- 测试覆盖：未覆盖。没有 320/360 宽度下分析页图表不横向溢出的测试。

### F15B-05（P3）表格危险链接的红色恢复依赖 3 个内联字符串，换一种红就被全局蓝字压掉

- 文件:行号：`frontend/src/index.css:7736-7750、8139-8156`
- 触发条件：表格里的危险操作链接改用 CSS class、`var(--crm-danger)`、`#d4380d`、`#dc2626` 等未被白名单覆盖的红色，或新增危险操作忘记写内联 `style={{ color: 'var(--crm-error)' }}`。
- 后果：`.semi-table-tbody .semi-table-row-cell a { color:#2c62d9 !important }` 会压掉普通 class 的红色；只有内联 style 字符串里含 `crm-error`、`#f53f3f`、`#ff4d4f` 三种字面量才恢复红色。当前仓库的表格红链接基本都写 `var(--crm-error)`，所以现状没看到漏网；但这是一条“新加/换色即失效”的隐式约定，删除/作废/停用可能重新变成普通蓝色，用户看不出危险。
- 证据代码：

```css
/* index.css:7736-7750 */
.semi-table-tbody .semi-table-row-cell a {
  color: #2c62d9 !important;
  font-weight: 400;
  text-decoration: none;
}

/* index.css:8146-8156 */
.semi-table-tbody .semi-table-row-cell a[style*="crm-error"],
.semi-table-tbody .semi-table-row-cell a[style*="#f53f3f"],
.semi-table-tbody .semi-table-row-cell a[style*="#ff4d4f"] {
  color: var(--crm-error) !important;
}
```

- 建议：不要用属性选择器猜内联颜色。表格危险操作统一用 `Button type="danger" theme="borderless"` 或加 `.cell-danger-link` 类，CSS 只认类；并补 `a.cell-danger-link { color: var(--crm-error) !important; }`。
- 测试覆盖：未覆盖。没有“表格危险链接必须是红色”的静态/组件测试。
