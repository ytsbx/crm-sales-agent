**我检查了什么：**

- 产品详情加载、SKU 列表、产品/SKU 编辑与新增、SKU 启停、产品删除。
- SKU 物理字段（长/宽/高/单重/装箱数/箱体积/起订量）的前端转换、负数/0/超大值/小数位。

**结果如何：**

- `toNumber` 对非数字返回 `null`，`Number.isFinite` 只挡 Infinity/NaN；`925-931` 把 7 个物理字段全部交给它，`SkuUpdate` 允许 `null`，所以用户把 `12cm`、`abc` 填进长/宽/高/单重时，保存会把原值清空，而不是报错。
- 后端 `field_rules.py:44` 的物理量最小值是 0；`SkuCreate/SkuUpdate` 用 `ge=0`，0 合法。`logistics.py:159-162` 只在 `weight is None` 时警告“没有维护单重”，0 会原样算进实际重量；而 `logistics.py:437` 对手工 `weight_override <= 0` 又是拒绝的——同一件事两条口径。

- 编辑 SKU/产品：`updateSku`/`updateProduct` 没有版本号；两个有 `product:manage` 的人同时编辑，后保存整份 payload 覆盖先保存。
- `productQuery` 失败时 `product` 为空，页面走 `!product` 分支显示“产品不存在或已下线”；`skuQuery` 失败时表格 `empty="还没有 SKU，先加一个"`。500/403 会被说成产品被删/没有 SKU。
- `skuImagesQuery` 失败没有 `isError`；`SkuImageCell` 预览失败只显示 `!`，不显示“图片读取失败”。用户会以为 SKU 没有图，可能重复上传。
- 主数据面板 `masterQuery`/`identityQuery` 用 `emptyTextNode`，错误态正确；本地确认后端有 `recheck` 分支和审计，不重复建版本。
- 权限门控：写入口都走 `product:manage`；成本/价格入口不在本页，未发现本页绕过。
- 事务边界：产品/SKU 保存是单请求；新建 SKU 是“建 SKU + 逐张上传图片”多请求，图片失败会留下已建 SKU（有明确 Toast），不是订单/收款那种半成品；但重复创建/重复上传见 F12-05/06/10。

#### F12-01 SKU 物理字段非数字输入被静默清空

- 严重度：P1（主数据丢失，影响运费）
- 位置：`frontend/src/modules/product/ProductDetailPage.tsx:131-136、925-931`；`backend/app/modules/product/schema.py:58-64、78-84`
- 触发条件：编辑已有 SKU，把长/宽/高/单重/装箱数/箱体积/起订量中任意一个有值的字段改成 `12cm`、`abc`、`1.2.3` 等非纯数字后保存。
- 后果：`toNumber` 返回 `null`，payload 把该字段作为 `null` 发 `PATCH /skus/{id}`；后端 `SkuUpdate` 允许 `null`，直接把原值清空。用户看到“SKU 已保存”，但单重/体积/尺寸已经没了。物流试算随后按 0/缺失算，可能少收运费。
- 证据代码：

```ts
// ProductDetailPage.tsx:131-136
const toNumber = (value: string): number | null => {
  const trimmed = value.trim()
  if (!trimmed) return null
  const parsed = Number(trimmed)
  return Number.isFinite(parsed) ? parsed : null
}
```

```ts
// ProductDetailPage.tsx:925-931
length: toNumber(skuForm.length),
width: toNumber(skuForm.width),
height: toNumber(skuForm.height),
weight: toNumber(skuForm.weight),
carton_qty: toNumber(skuForm.carton_qty),
carton_volume: toNumber(skuForm.carton_volume),
moq: toNumber(skuForm.moq),
```

- 建议：物理字段用严格十进制解析（`parseOptionalDecimal` 或自建 `^\\d+(\\.\\d+)?$`），空串才返回 `null`；非法文本按字段名提示并中止保存。后端 `SkuUpdate` 可再加“字段出现且为 null 时是否允许清空”的显式语义，避免和“没传”混淆。
- 测试覆盖：**未覆盖**。`test_sku_optional_code.py` 只测 SKU 编码；`test_sku_master_authority.py` 测主数据核定；没有前端非数字输入/清空字段用例。

## 四、补充维度核对

### 负数 / 0 / 超大值 / 小数位

| 页面 | 字段 | 前端 | 后端 | 结论 |
| --- | --- | --- | --- | --- |
| 产品详情 | SKU 长/宽/高/单重 | 文本 `Input` + `toNumber`，非数字→null；负数/0 原样传 | `ge=0, max_digits=12, decimal_places=3` | 负数/超限/超 3 位小数 422；0 通过（F12-02）；非数字静默 null（F12-01） |
| 产品详情 | 装箱数/起订量 | 同上，小数也原样传 | `ge=0, le=10^12-1` 整数 | 小数/超限 422；0 通过 |
| 产品详情 | 箱体积 | 同上 | `ge=0, max_digits=12, decimal_places=4` | 0 通过；超 4 位小数 422 |
| 产品列表 | 产品名称/产品线/品牌/描述 | 只判名称非空，无长度上限 | `name` 200、`category` 64，其余自由文本 | 超长名称提交才 422；其他无强约束 |
| 物流 | 数量 | `Number()`，只判有限且 >0 | `LogisticsCalculateRequest.quantity: Decimal` **无 gt/max_digits** | 负数/0 前端拦住；超大值/16 位可进后端（F12-08） |
| 物流 | 重量/体积覆盖 | `parseOptionalNumber`，<=0/NaN 禁用试算 | `Decimal` 无 `ge` | 前端拦住 0/负数；API 直连可传 0/负数（非页面路径） |
| 物流 | 运费/计费重 | number、`toFixed(2)` | `_f` 转 float | 16 位/4 位小数丢（F12-08） |
| 收款计划 | 比例 | `InputNumber min=0 max=100 precision=2`，提交前 `planBlockedReasons` 判 >0/合计 100 | 后端 `ReceivableGenerate` 复用校验 | 0/超 100/小数位有拦截；金额 exact 预览 |
| CSV 导入 | 文件 | `.csv` + 预览校验 | 逐行校验 + `preview_token` | 前端不解析数值，后端行级 422/跳过 |

### 事务边界

- 产品创建、产品更新、SKU 更新：单请求；没有“产品建了 SKU 没建”的前端路径。
- 新建 SKU：单请求建 SKU + 逐张上传图片，是多请求；图片失败不会回滚已建 SKU，会 Toast“SKU 已创建，有 N 张图片没传上”。这是明确的“保住主记录、图片可补”的业务取舍，不是订单/收款半成品；重复建见 F12-06，重复上图见 F12-10。
- 物流保存：单请求写 `logistics_quotes`；没有半条记录；重复保存见 F12-07。
- CSV 导入：预览 `session.rollback()` 不落库；确认带 `preview_token`，文件/结论/目标原值任一变化整体回滚 409；没有半条导入。
