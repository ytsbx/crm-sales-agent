**位置**

- `backend/app/modules/analytics/targets.py:751-759`（`sales_variance` 用 `float(actual) - float(target)`）

**触发条件**：目标金额是 Decimal、包含分位/大额，或需要从审计日志重建“改前/改后”目标。

**后果**：审计快照和保存响应无法精确还原到分；`sales_variance`/`repeat_customer_variance` 走 float 后可能与 `*_variance_exact` 不一致；大额（接近 16,2 上限）时 float 精度不足，审计复算会对不上。

**证据代码**
```python

"repeat_customer_target": float(row.repeat_customer_target or 0),
# targets.py:751-758

actual = float(row.get("assess_actual") or 0)
row["sales_variance"] = round(actual - target, 2)
```

**建议**：审计/接口金额统一使用字符串 exact（`str(Decimal)` 或现有 `*_exact`）；float 只作为展示字段，并明确“不要用于复算”。目标保存响应补 `sales_target_exact`/`repeat_customer_target_exact`，审计快照直接写 exact。

**测试覆盖**：部分覆盖但不覆盖精度。`test_target_scope_input.py` 测 `SalesTargetUpsert` 的 Decimal 边界，`test_review_round46_repairs.py:209-224` 测目标 upsert 乐观并发；没有“审计快照/响应含 exact”的断言。

### B18-03 P2 已冻结期间缺某个指标键时回落实时值，冻结报表仍会漂移

**位置**
- `backend/app/modules/analytics/targets.py:697-715`（`frozen_row` 以 `(scope_key, "sales")` 为锚点，缺键 `return live`）
- `backend/app/modules/analytics/targets.py:726-740`（覆盖四项/复购，最后 `actual_frozen=True`）

**触发条件**：历史快照只写了部分指标（例如 `repeat_net` 是后加的字段，旧版本结账的快照没有这一项），或人工清理/迁移后某个键缺失；该期间仍被判定为已冻结。

**后果**：同一期“已结账”的报表里，缺项指标继续跟着实时订单/回款变化，而 `actual_frozen` 仍显示冻结；复购差额/达成率会在结账后被退货、改单改变。用户会相信“这期不会再变”，但数字其实还在变。

**证据代码**
```python
# targets.py:709-715
if frozen_row:
    def frozen_value(metric: str, live):
        key = (scope_key, metric)
        if key not in snap:
            return live          # ← 冻结期缺项回落实时
# targets.py:740
row["actual_frozen"] = frozen_row
```

**建议**：冻结期内缺项应按 0 处理，或显式返回 `missing_frozen_metric` 并**不能**标 `actual_frozen=True`；若历史快照不完整，应阻止结账/重算或做一次性补全迁移，不能静默用实时值。补一条“冻结期缺 repeat_net/new_customer”的测试。

**测试覆盖**：未覆盖。`test_target_freeze_limits.py` 只测金额溢出/整批原子性；没有“冻结快照缺键”的用例。
