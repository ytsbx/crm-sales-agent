### B08-03｜P2｜模板备注没有 255 长度校验，超长直接数据库 500

### B08-04｜P3｜`_cancel_safe` 被取消后重试复用同一个 coroutine，第二次 `shield` 必抛 `RuntimeError`，清理不会重试

- **位置**：`backend/app/modules/contract/service.py:915-947`；调用点 `contract/router.py:596-604`、`bizdoc/router.py:265-275` 等
- **触发条件**：合同/单据生成把 PDF 落盘后，请求在写审计/提交阶段被取消（客户端断开、超时、优雅停机）；`_cancel_safe` 第一次 `await asyncio.shield(coro)` 收到 `CancelledError`，进入重试循环。
- **后果**：`asyncio.shield` 第一次已经把同一个 coroutine 交给内部 Task；外层取消不取消内部 Task，coroutine 仍被它持有。第二次 `shield(coro)` 会对同一个 coroutine 再建 Task，抛 `RuntimeError: cannot reuse already awaited coroutine`，被 `except Exception` 记成“清理失败”后返回。`cleanup_pending_objects` 已经在入口 `take_pending_objects` 取走并清空了登记，于是本次 PDF 成为孤儿，且不会再有第二次清理。不是金额/数据丢失，是存储泄漏 + 清理日志误导。
- **证据代码**：
  ```python
  for attempt in range(_retries + 1):
      try:
          return await asyncio.shield(coro)
      except asyncio.CancelledError:
          ...
          logger.info("...重试第 %d 次", attempt + 1)
  ```
  ```text
  本地最小复现：
  first cancelled
  second error RuntimeError cannot reuse already awaited coroutine
  ```
- **建议**：每次重试新建 coroutine（把清理逻辑写成可重复调用的函数/工厂），或保留第一次 `shield` 返回的 Task 引用并 `await` 它；不要对同一个 coroutine 反复 `shield`。失败时不要把“登记已取走”当成“已清理”，应保留可重试标记或写死信队列。
- **测试覆盖**：未覆盖。`backend/tests/test_upload_cleanup_cancellation.py` 测的是文件上传服务的 `discard_unregistered_upload`，不是合同 `_cancel_safe`；`test_round4_review_fixes.py:240-350` 只测 `cleanup_pending_objects` 的核查语义，没有注入“清理期间取消 + 重试”。

### B08-P1｜签署登记只校验文件“可见”，不校验它是否已作为别的合同的签署件

- **位置**：`backend/app/modules/contract/router.py:673-675` + `contract/service.py:1239-1269`
- **证据**：路由只调 `can_access_file(session, user, file_id)`；该函数是“文件挂在任一当前用户可见的业务对象上即放行”。服务只排除本合同的 `generated_file_id`/任何 `generated` 附件，没有查“该 `file_id` 是否已以 `category=signed` 挂在另一份合同上”。因此同一份签署扫描件可以被两份合同同时登记为 `signed`。
- **需要业务确认**：是否允许一份扫描件服务多份合同（例如同一客户同日两份补充协议共用一张签字页）？若不允许，应加 `BusinessFile` 的 `(file_id, category=signed)` 唯一或服务层“已签给别的合同则拒绝”；若允许，应在详情页明示“该文件同时是合同 X 的签署件”。当前没有判据，暂不定级。

### B08-P2｜对客报价 Excel 的金额/单价是文本，客户不能直接求和/公式引用

- **位置**：`backend/app/modules/bizdoc/xlsx.py:117-130`、`:300-315`
- **证据**：`_cell_text("amount")` 返回 `f"{Decimal(...):,.2f}"` 字符串（含千分位逗号）；`_cell_text("unit_price")` 返回 `format_unit_price` 字符串；写单元格时直接 `sheet.cell(value=...)`，没有设置数值类型/`number_format`。Excel 打开后这些格是文本，`SUM` 会得到 0，改数量也不会自动重算金额。
- **需要业务确认**：对客报价单是“只读展示件”还是“客户可改数量重算的工作表”？若是后者，金额/单价应写数值并设 `number_format`（`#,##0.00` / 单价 4 位），同时保留一份精确字符串在快照/审计里。当前未定级。
